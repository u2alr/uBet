## What this pass found and fixed

1. **The model counted Tatum out from a stale ESPN note** for a game the NBA report had not covered (Boston 57%, now 62%). The model and both pages now read the NBA report only.
2. **A name bug**, "Jimmy Butler I II", from spacing a run-together PDF name twice.
3. **A stale-looking report time**: the page now shows the report's own time and how old it is, and the helper reads the report every 15 minutes.
4. **The health check called the live site "degraded" for something switched off** (player-prop projections) and never looked at what the pages need. It does now.
5. **A vacuous test**: my first property test for lineups never applied a single flag, so a planted bug survived. Found by the mutation check, fixed, and the test now asserts it applied flags.
6. **The injury-report downloader read missing files as throttling** and crawled (50 of 3,884 in an hour); fixed (a 403 from this server means the file does not exist, confirmed against a known file).
7. **The Review numbers and README were out of date** with what the app now is.

## What the new evidence says about the model

* The NBA's "Out" is as reliable as hindsight (about 38 of 37,873 listed-Out players played), "Doubtful" plays 2.5%, "Questionable" 50.4%, "Probable" 90.7% (2020-21 to 2025-26). Treating only listed Out as absent loses 0.003 to 0.006 log loss against knowing who actually played, and adding status-aware expected loss recovers about a tenth of that (consistently positive, not significant). Nothing was adopted.

## What is capped, and what would lift it

* **Calibration (6)**: needs sportsbook prices for the games the model predicts. The live comparison fills at about 5 to 10 games a day, so roughly 5 to 8 weeks to its 300-game minimum. Nothing in code shortens that.
* **Data coverage (7)**: historical closing lines (a paid odds plan) and the lineups posted 30 minutes before tip.
* **Not verified from here**: the two GitHub workflows (syntax only), the scheduled-task installer (dry run only), and the live database steps (`npm run setup:remote`), which write to production and are for you to run.
