## Findings

1. **Margin removal biased the market's chance (fixed).** Proportional removal gives the favourite too little. Example at 1.30 / 3.90 the power method gives the favourite more than proportional (tested). It shifts our "edge" by up to about a point on lopsided games.
2. **Integration tests are not hermetic and were Windows-only (partly fixed).** Fixed: cross-platform server shutdown, longer start wait (wrangler spends about 30 s trying to reach Cloudflare on a restricted network), clear error when `player_games` is empty. Open: the tests name real players (Cunningham, Wembanyama, Brown), so they need a synced local database and cannot run in CI. A seeded fixture database would fix that; it is a larger change.
3. **Stale best price (fixed).** See above.
4. **Stale model snapshot (fixed).** See above.
5. **Single-book recommendations (fixed).** A game only one book priced could be listed under "best" from a model/market gap alone. It no longer is.
6. **Credit-budget cap is no longer needed on this branch.** Pages read stored odds (`odds_snapshot`); the provider is called only before the first sync or with the privileged `?fresh=1`. The free plan limit is requests per minute and is paced by the sync script.
7. **Deliberately not changed: the logged market chance.** `research/defense_snapshot.py` logs the ESPN market chance with proportional removal into `game_lean_log`. The live comparison is pre-registered, so switching method mid-stream would mix two definitions in one record. Change it only together with a new logging version.
8. **Open, needs data:** no evidence the model beats sportsbook prices (`research/MARKET_EVAL_STATUS.md`); blend weight 0.3 is a placeholder; late scratches and real lineups are not seen.
