## Findings, most serious first

1. **Moneyline (team) legs can no longer be added anywhere.** (High, my change.) Removing Team bets from the Props page left `TeamBets.tsx` imported by nothing, and it was the only caller of `toggleTeam`. The slip, the dock and `shared/teamBets.ts` still handle team legs, and saved ones still load. Either give team legs a new entry point (for example the market cell of a game row) or remove the dead code and the plumbing on purpose.
2. **Integration tests read your `.dev.vars`.** (High for trust in the suite.) With `ODDS_HOURS=24`, 14 of 75 tests fail, because the fake odds server places games up to 36 hours out. With that line removed, 75 of 75 pass. (Correction to the first draft of this report: the harness already pinned `ODDS_MAX_EVENTS`, so only `ODDS_HOURS` leaked in.) **Fixed:** the harness now pins `ODDS_HOURS`, `ODDS_MAX_EVENTS` and `ODDS_REGIONS` unless a test overrides them, and retries cleanup when Windows holds a file lock.
3. **Undersized tap targets.** **Fixed** (both toggles are now 28 px; only two 13 px checkboxes with clickable labels remain). (Medium, my change.) The "Why the over/under?" toggle on every card and the "Why & game info" toggle are 16 px tall, below the 24 px minimum. 39 controls in total, plus two 13 px checkboxes whose labels are clickable. Fix: add vertical padding to both toggles.
4. **No running credit budget.** (Medium.) Protection is the per-fetch event cap and an 8-hour cache. With 15 games and 4 markets a full slate is about 60 credits per cache window, so roughly 180 a day if the app is open all day, against about 500 a month on the free plan. On a deployed copy any visitor's ordinary page load can trigger the fetch on a cache miss (only `?fresh=1` is privileged). Fix: a persisted monthly counter that stops fetching near a limit, or fetch only from a privileged refresh or schedule.
5. **`check:config` always fails.** **Fixed:** the scanner skips values carrying the repo's `not-real` marker, the fixture token now has it, and a test shows the marker in a comment does not excuse a real-looking value; `check:config` exits 0. (Medium.) Its secret scanner flags the dummy token `integration-token-value-0123456789` at `tests/integration/ops.test.mjs:7`. A check that always fails gets ignored, and it would hide a real leak. Fix: allow-list that fixture or give it an obviously fake shape.
6. **Slip write is unguarded.** **Fixed:** writes go through a guarded `save`; verified with storage forced to throw. (Low.) `src/lib/slip.tsx:13` calls `localStorage.setItem` without `try/catch`, while the read two lines up has one. In a browser with storage blocked, adding a leg can throw.
7. **SQL built from interpolated values.** **Fixed:** `tierRow` binds `mind` and `tier`. (Low, safe today.) `tierRow` in `functions/api/[[route]].ts:975` interpolates `mind` and `tier`; every caller passes a literal, so it is not exploitable now. Pass them as bind parameters so a future caller cannot make it unsafe.
8. **Game rows lost their heading element.** **Fixed:** the row button sits in an `h3`, and `aria-controls` is set only while open. (Low, my change.) The row is now a button inside a `section` with an `aria-label`. Screen-reader heading navigation no longer lists games. `aria-controls` also points at an id that does not exist while a section is closed.
9. **Left rail highlight does not follow scrolling.** (Low.) It shows the game you last clicked, not the one in view.
10. **Operations notes.** (Info.) `CAPTURE_TOKEN` is unset (safe default: writes only from localhost), and `wrangler.toml` still holds the placeholder D1 id, so a production deploy needs both set first.
